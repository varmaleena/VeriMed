# Phase 1 CKS reference-client verification

This slice implements public-reference retrieval, not a deployed CKS service or clinical safety engine.
UI work is deferred. No new AWS resources were created by these checks.

Run from the repository root in PowerShell:

    .venv/Scripts/python.exe -m pytest services/cks/tests -q
    ./scripts/Test-CksReferences.ps1

The live command accepts only a de-identified drug name/strength through -Drug.
Never supply patient notes or identifiers. Input validation is not a PHI scrubber.
Each run replaces docs/cks-verification.json with public-reference metadata and response hashes;
the report contains no label prose or clinical records.

On November 19 the metformin query produced one normalized candidate; exact lookup of its
preferred name produced two concepts. No RxCUI was selected automatically.
Candidate transport probes fetched 32 and 34 class memberships and three labels each.
Both class results require review for unspecified relationships; label totals were 95 and 79,
so the three-label responses are explicitly partial. These checks passed transport/parsing,
not clinical correctness or a complete safety assessment.

The library uses bounded asynchronous HTTP, timeouts, retries, strict response schemas,
source provenance, OTel fetch spans, and structured outcome logs/metrics without query text.
Unit tests use doubles only inside tests and cover malformed providers, ambiguity, missing
coverage, timeouts, redirects, query validation, and log redaction.
Per-client spacing is not a distributed production quota limiter.

The JSON contract is packages/api-client/cks.schema.json, generated by services/cks/export_schema.py.
CI regenerates it and checks for drift. No network-facing endpoint is exposed by this slice;
authentication, authorization and cross-account negative tests must accompany service deployment.

The enterprise target is a separate PHI-free hub account with PrivateLink access from cells.
Only the standalone dev-cell profile is configured. See BLOCKERS.md and ADR 014.
Hub hosting, PrivateLink, Valkey caching, reference mirroring and Phase 1 deployed acceptance
are pending. Public API smoke probes create no AWS charges; no new AWS spend was incurred here.

Validation: 73 Python unit tests passed (21 CKS, 52 API), Ruff check/format passed,

## Fresh-only Valkey cache slice — November 19

CachedKnowledgeClient wraps the real reference client with ValkeyStore. It preserves source dates
and review flags and expires results within one hour of the oldest source. It never stores errors
or negative lookups. Corrupt/stale entries and cache outages trigger fresh provider calls;
if that call fails, the result remains UNVERIFIED. Cache hashes detect corruption, not hostile writes:
production requires isolated networking, ACL credentials, TLS, and service authorization.

ValkeyStore requires valkeys:// with certificate and hostname verification outside explicitly enabled
loopback development. URLs with query-string overrides are rejected. VALKEY_URL can contain credentials;
do not print it or commit it. Dispose the store with await store.aclose() at process shutdown.

Real integration, from repository root with the Compose Valkey service running:

    $env:VALKEY_URL = "valkey://127.0.0.1:6379/0"
    .venv/Scripts/python.exe services/cks/cache_integration.py --allow-local

This checks a unique transport key's round trip and expiry, then queries live RxNorm twice and proves
the second lookup retains the original provenance without another provider request. It temporarily
replaces the metformin cache key; run only against an isolated development/test cache.
The script deletes its keys afterwards. Failure returns nonzero. No provider responses are fabricated.
CI runs this against a real Valkey 9.1.3 service; upstream connectivity failure fails the check.

Local real-server integration is unverified: Docker is unavailable and WSL is not installed.
No Git remote is configured, so the new hosted CI job has not run. No AWS cache was deployed.
The existing live-provider report predates this cache slice and is not evidence of real cache execution.

Cache-slice validation: 101 unit tests passed (52 API, 49 CKS), including 28 cache tests.
Ruff and strict mypy passed across 34 source files. TLS constructor tests were rerun after the
final constructor typing fix. Three pre-existing framework deprecation warnings remain.
Real-Valkey integration and hosted CI remain unverified for the reasons above.

## Private service-boundary slice — November 19

The FastAPI service exposes POST /normalize, /classes, and /labels using strict request/response types.
No patient IDs, encounters, notes, or caller-selected tenant IDs are accepted.
It preserves UNVERIFIED/REVIEW_REQUIRED results; an HTTP 200 lookup is not clinical approval.
Malformed inputs return redacted 422 problem responses; provider exceptions and deadline expiry return
503 problem responses with trace IDs. Bodies are limited to 16 KiB and requests to 20 seconds.
URL query parameters are rejected, browser schema/docs routes are disabled, and responses use no-store.

Authentication is performed by an AWS_IAM private REST API. The app checks only trusted Lambda proxy
requestContext metadata, including API, stage, hub account, calling role/account, and per-role endpoint.
Role bindings determine the tenant and allowed operations. Headers cannot establish identity.
This app must not be deployed as an independently public ASGI service. Its Lambda adapter requires
gateway-only invocation permissions: anyone with direct Lambda invoke rights could forge gateway metadata.

CksIngress in infra/cdk/cks-ingress.ts is an integration construct, not a deployed HubCKS stack.
It accepts an existing Lambda-compatible runtime and explicit CksCaller bindings, requires private API
ingress and AWS_IAM methods, and restricts resource-policy access to approved roles/endpoints.
It emits runtimeEnvironment settings for the runtime:
CKS_API_ID, CKS_HUB_ACCOUNT_ID, CKS_STAGE, and CKS_CALLERS_JSON.
The latter maps role_arn, tenant_id, endpoint_ids, and operations; it must come from deployment configuration.
Do not invent IDs or account bindings. Cell invoke policies and endpoint policies must be deployed alongside it.

Tests cover unsigned requests, forged headers, wrong roles/accounts/endpoints, operation denial,
tenant override rejection, payload bounds, redacted errors and timeouts, and review-state preservation.
The OpenAPI and TypeScript contracts are packages/api-client/cks.openapi.json and cks-api.d.ts.
Run:

    .venv/Scripts/python.exe -m pytest services/cks/tests/test_service.py -q
    pnpm --filter @verimed/cdk test

Remaining gates: separate hub account/profile; actual runtime packaging/deployment; private endpoint
and cell IAM policies; a no-NAT plan connecting the runtime to both private Valkey and public reference
providers; mirrored reference storage; distributed provider quotas; real cross-account signed-call tests.
The ingress construct alone neither deploys the runtime nor solves private-cache/public-provider connectivity.
The existing live reference report does not prove service authentication or PrivateLink connectivity.
No resources were deployed or AWS charges added by this slice.

Service-boundary validation: 121 Python tests passed (52 API, 69 CKS), including 20 service
authorization/error-boundary tests. All 12 CDK tests passed; the CKS ingress synthesis passed cdk-nag
with the explicit acknowledgements in source. Strict mypy passed across 36 source files.
Ruff, TypeScript compilation, targeted ESLint and generated-contract formatting passed.
These are local unit/synthesis results; hosted CI and real signed cross-account calls remain unverified.

## No-NAT HubCKS runtime — November 19

HubCKS now composes the private IAM ingress, an isolated API Lambda, authenticated Valkey serverless,
and an IAM-only non-VPC reference worker. The private API has no direct internet path. It invokes the
worker through the Lambda interface endpoint; only the worker performs fixed-host NLM/FDA requests.
The worker cannot read cache secrets. The API reads one generated secret through a scoped Secrets Manager
endpoint and uses TLS with certificate/hostname verification. No password is stored in Lambda environment
variables. Both API and worker have bounded requests, redacted failures and W3C-linked OTel spans.
A CDK helper Lambda also removes the VPC default security group's default rules.

Synthesis requires VERIMED_CKS_BUNDLE, VERIMED_HUB_ACCOUNT, VERIMED_CELL_ACCOUNT (different accounts),
VERIMED_CKS_CALLERS_FILE and CKS_CACHE_MAJOR_VERSION. The callers file is an explicit JSON array of
roleArn, tenantId, endpointIds and operations. Obtain actual IDs from cell deployment; do not use CI bindings.

Build the Linux runtime:

    ./scripts/Build-CksBundle.ps1

The script prints a new ignored bundle directory containing locked, hash-verified Linux dependencies,
application modules and build-manifest.json. Set VERIMED_CKS_BUNDLE to that bundle, not services/cks.
Only then synthesize HubCKS with the configured separate-account caller bindings:

    pnpm --filter @verimed/cdk exec cdk synth HubCKS -c hubCks=true

The regional engine catalog returned Valkey 7.2 through 9.1 on November 19. Engine major is explicit
configuration; successful serverless creation is still a live deployment check. The Linux native extension
was verified as CPython 3.12 x86_64 Linux, but local Linux execution is unavailable without Docker/WSL.

This supersedes the unresolved private-cache/public-provider connectivity design noted above.
Deployment is still blocked by the missing hub account/profile and actual cell endpoint/role configuration.
Reference Postgres mirroring, a distributed provider quota limiter, cache credential rotation, redundant
endpoint placement, alert destinations, and real cross-account tests remain unfinished.
The app now rejects RESOLVED responses without supporting evidence, including contradictory selected
concepts, unspecified class relationships and incomplete label coverage.

No-NAT runtime validation: 145 Python tests passed; all 13 CDK tests passed, including HubCKS
synthesis with cdk-nag. Ruff/strict mypy passed across 41 source files, and TypeScript/ESLint passed.
A fresh hash-verified Linux bundle was built successfully. No hub deployment or Linux runtime execution
was claimed. The optional worker request contract is cks-reference-request.schema.json.
